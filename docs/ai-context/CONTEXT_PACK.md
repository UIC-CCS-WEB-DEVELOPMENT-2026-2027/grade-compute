## 1. The app

CompUGrade is a single-page web app for college students. It turns a syllabus's grading rules into
a dashboard. Students:

- track their official grades
- enter their own (self-reported) scores
- see how each grade is computed
- work out what they need to reach a target grade (the Target Grade Sandbox)

Only the student experience exists. There is no backend and no network call. All data lives in
the browser's `localStorage`.

## 4. Rules (numbered so a review can cite them)

**Code**

- **R1.** Named exports only: `export function Foo()`. No `export default`. ⟦TBD-2: list any file
  that still needs a default export because a tool requires it, or "none".⟧
- **R2.** Names: `PascalCase` components and files, `useCamelCase` hooks, `camelCase` functions and
  variables, `UPPER_SNAKE_CASE` constants.
- **R3.** Grade computation, rounding and formatting are pure functions in `lib/`. Components call
  them and never redo the maths inline. Reuse the existing functions (§7) before writing new ones.
- **R4.** Read and save the database only through `useDb` / `services/db.js` (§7). Never touch
  `localStorage` directly in a component.
- **R5.** No commented-out code, no unused imports, variables, exports or files.
- **R6.** Prettier style: 4-space indent, double quotes, semicolons, trailing commas, 100-column
  lines.
- **R7.** A comment above each component says what it is and documents props that aren't
  obvious, in plain sentences (see §9).

**Styling**

- **R8.** Tailwind utility classes only. Never write a `.css` file, a `<style>` tag, CSS modules,
  CSS-in-JS or a `style={{…}}` object. One exception: `style` may pass **runtime user data** as a
  CSS variable (for example a criterion's colour or a depth: `style={{ "--pill-depth": depth }}`).
- **R9.** Colours only through the tokens in §5.1 (`bg-primary`, `text-muted-foreground`,
  `border-border`, opacity modifiers like `bg-primary/10`). Never `#hex`, `rgb()`, `hsl()`,
  named colours, or Tailwind palette colours (`bg-blue-500`, `text-gray-600`, `bg-white`).
- **R10.** No arbitrary values: no `text-[13px]`, `w-[347px]`, `mt-[7px]`, `bg-[#…]`. Use the
  Tailwind scale or a token. A CSS-variable reference like `z-(--z-modal)` is allowed. If a value
  is missing, say a token is needed instead of inventing one.
- **R11.** Text size, weight, line height and font come from a text role (§5.2), never from
  `text-sm`, `text-xl`, `font-bold` or `leading-*` on their own.
- **R12.** Controls use the control sizes (§5.3), and every element of the same kind has the same
  size.
- **R13.** Mobile-first: base classes are for phones, then `sm:` / `md:` / `lg:` / `xl:` upwards.
  Only the Tailwind default breakpoints (§5.6).
- **R14.** Every screen works at 375, 768, 1024 and 1440 px wide: no horizontal scroll, nothing
  clipped or overlapping. Use flex, grid, `min-w-0`, `max-w-*`, not fixed pixel widths.
- **R15.** Touch targets are at least 44px on phones and tablets. ⟦TBD-3: the exact convention
  agreed in Phase 8, e.g. `max-lg:h-control-touch` vs `max-md:h-control-touch`, and whether
  `Button` / `Input` already apply it themselves.⟧

**Components**

- **R16.** Use the shadcn component from §6.1 for anything it provides: button, input, select,
  dialog, alert dialog, card, tabs, tooltip, popover, switch, checkbox and so on. Never hand-build a
  `<button className="…">` that imitates `Button`, or a modal `<div>`.
- **R17.** Keep the shadcn components' structure and API. Pass `className` to adjust them. Don't
  copy their code into a feature file.
- **R18.** If you need a shadcn component that isn't in §6.1, say so. The owner adds it with the
  shadcn CLI. Don't write it from memory.

**Accessibility**

- **R19.** Every interactive element has an accessible name (visible text, `<label>`/`FieldLabel`,
  or `aria-label`) and a visible focus state (the shadcn components have one; for custom
  focusable elements use `focus-visible:ring-3 focus-visible:ring-ring/50`).
- **R20.** Text contrast meets WCAG AA. Use the `-foreground` token that pairs with a fill.
  `warning` and `highlight-strong` are fills only, never text colours.
- **R21.** Decorative icons get `aria-hidden="true"`.

**Product**

- **R22.** Don't change user-facing wording, how a grade is computed, rounded or displayed, the

- **R23.** Don't touch branding: the logo, `BrandMark`, the product name "CompUGrade", the favicon or

- **R24.** Build only for the **student** role. Leave professor, parent and admin code (the

## 5. Design vocabulary (the only values you may use)

### 5.1 Colour tokens (Tailwind names)

Use them as `bg-*`, `text-*`, `border-*`, `ring-*`, `fill-*`, `stroke-*`, with `/NN` opacity where
needed.

| Token | Use for |
| --- | --- |
| `background` / `foreground` | page background / standard text |
| `card` / `card-foreground` | cards, tables, dialogs |
| `popover` / `popover-foreground` | popovers, menus, tooltips |
| `primary` / `primary-foreground` | main actions, active states, headings |
| `secondary` / `secondary-foreground` | soft blue fills, secondary buttons |
| `accent` / `accent-foreground` | hover backgrounds |
| `muted` / `muted-foreground` | quiet fills / helper and secondary text |
| `border`, `input`, `ring` | dividers, input outlines, focus rings |
| `overlay` | dialog and menu backdrops |
| `destructive` | error text and destructive actions |
| `success` / `success-foreground` | success states |
| `warning` / `warning-foreground`, `warning-soft` | coral warnings (fill only), soft warning fill |
| `highlight` / `highlight-foreground`, `highlight-soft`, `highlight-strong`, `highlight-text` | yellow banners and pending states; `highlight-strong` for fills, markers and rings only; `highlight-text` for yellow-family text |
| `official` | locked official scores |
| `self-reported` / `self-reported-foreground` | student-entered values: `self-reported` for fills, dots, rings and borders; `-foreground` when the value is text |
| `criteria-1` … `criteria-8`, each with `criteria-N-on` | the colours of grading-rule criteria; `-on` is the text/dot colour on that fill |
| `sidebar`, `sidebar-foreground`, `sidebar-primary(-foreground)`, `sidebar-accent(-foreground)`, `sidebar-border`, `sidebar-ring` | the sidebar only |

Criteria colours are picked at runtime with `getCriteriaColor(n)` / `getCriteriaOnColor(n)` from
`@/lib/rules`, which return `var(--color-criteria-N)`. Pass them through a CSS variable in `style`
(R8), never as a hard-coded colour.

### 5.2 Text roles

Use exactly one `type-*` class for each piece of text. Add colour with a token (`text-primary`,
`text-muted-foreground`). Weight changes inside the role (`font-semibold`) are fine for General
Sans roles.

| Class | Font | Size (phone → `md` and up) | Use |
| --- | --- | --- | --- |
| `type-display` | Khand 600 | 40 → 48px | the login hero heading only |
| `type-page-title` | Khand 600 | 30 → 36px | the page's `h1` |
| `type-section-title` | Khand 600 | 24 → 30px | section headings (`h2`) |
| `type-card-title` | Khand 600 | 20px | card titles (`h3`) |
| `type-body` | General Sans 400 | 16px | running text |
| `type-small` | General Sans 400 / 600 | 14px | helper text, table cells, buttons, inputs |
| `type-caption` | General Sans 600 | 12px | chart axes, badges and eyebrow labels **only** |

- Only two fonts exist: Khand (`font-heading`) and General Sans (`font-sans`, the default). Never
  add another.
- Weights are 400, 600 and 700 only.
- Nothing below 14px except `type-caption`.

### 5.3 Control sizes

| Class | Size | Use |
| --- | --- | --- |
| `h-control` / `size-control` | 40px | default button, input, icon button |
| `h-control-sm` / `size-control-sm` | 32px | `sm` buttons (desktop only) |
| `h-control-lg` / `size-control-lg` | 48px | `lg` buttons |
| `h-control-touch` / `size-control-touch` | 44px | phone and tablet touch size (R15) |

The shadcn `Button` and `Input` already use these sizes. Don't override a control's height with
any other value.

### 5.4 Spacing, layout and radius

- Tailwind 4px spacing scale only (`p-4`, `gap-6`, `mt-2`). Half steps like `gap-1.5` are fine.
- Card padding: `p-6` (24px), `p-4` on phones. Gap between cards: `gap-4`.
- Page gutters come from `PageShell`. Don't add page-level padding.
- Radius: `rounded-sm` 4px, `rounded-md` 6px, `rounded-lg` 8px, `rounded-xl` 12px, `rounded-2xl`
  16px, `rounded-3xl` 24px, `rounded-full`.

### 5.5 Shadows, layers and motion

- Shadows: `shadow-card`, `shadow-hover`, `shadow-dialog`, `shadow-row-active` (the bar on the left of
  the row being edited). No other shadows.
- Layers: `z-(--z-raised)`, `z-(--z-chart-tooltip)`, `z-(--z-header)`, `z-(--z-sidebar)`,
  `z-(--z-popover)`, `z-(--z-modal)`. No numeric `z-10` etc. shadcn overlays handle their own
  stacking.
- Motion: reduced motion is handled globally. Existing animation utilities are
  `animate-auth-*`, `animate-celebration-*`, `animate-record-highlight`; `animate-delay-<ms>` sets
  a delay. Don't add keyframes.

### 5.6 Breakpoints

`sm` 640, `md` 768, `lg` 1024, `xl` 1280 (Tailwind defaults). The JS sidebar thresholds match:
phone up to 767px (`useIsMobile`), tablet up to 1023px.

## 7. Data and logic you can call

**Database**

- `const [db, setDb] = useDb()` from `@/hooks/useDb`. It re-reads when anything saves.
  `useDb({ live: false })` sees only its own saves.
- `getDb()`, `saveDb(db)`, `saveDbSafely(db)` from `@/services/db`. `saveDb` fires the
  `compugrade-db-updated` event so other components refresh.
- `getActiveStudentId(db)`, `getActiveUser(db)`, `signOut()` from `@/services/session`.
- `updateStudentRecord(db, classId, studentId, update)` from `@/services/records`.
- Treat `db` as immutable: build a new object and save it. Don't mutate it in place.

**Data shape:** paste the "Data model" section of `SPEC.md` (§5) when the task reads or writes
data. In short: `users`, `computationRules` (a criteria tree with weights), `subjects`, `classes`
(enrolments, each with `studentRecords`), and per record `grades[term][leafCriterionId]` = an array
of tasks with `maxScore`, `officialScore` and `studentReportedScore`.

**Grades — the 3-state model:** a score is either **official** (entered by the school, locked, shown
with `official`), **self-reported** (entered by the student, shown with `self-reported`), or
**empty**. The "official" grade uses official scores only; the "expected" grade also counts
self-reported ones.

**Pure functions in `lib/`** (names only; paste the file if a task needs the details):

- `@/lib/grades`: `calculateOfficialGrade`, `calculateUnofficialGrade`, `calculateOfficialFinalGrade`,
  `calculateUnofficialFinalGrade`, `withStudentScore`, `getOfficialAssessments`, `toTaskList`
- `@/lib/format`: `formatGrade(value, { decimals })` (always use it to show a grade),
  `getGaugeProgress`, `getInitials`, `getSpaceSplitInitials`
- `@/lib/rules`: the rule tree editor and rule CRUD (`getCriteriaColor`, `getEffectiveShares`,
  `formatPercent`, `createRule`, `updateRule`, `deleteRule`, …)
- `@/lib/sandbox`: the Target Grade Sandbox plan (`getSandboxPlan`, `requiredScore`,
  `setDraftScore`, `withDraftScores`, …)
- `@/lib/targets`: `DEFAULT_TARGET`, `getTermTarget`, `getSandboxTarget`, `getSubjectDetailTarget`
- `@/lib/history`: grade history and chart data
- `@/lib/subjects`: `PASSING_GRADE`, semesters, `getEnrolledSubjects`, `addSubject`
- `@/lib/terms`: `TERMS`, `TERM_KEYS`, `TERM_LABELS`, `getTermLabel`, `toTermKey`
- `@/lib/scores`: `validateScore`. `@/lib/number`: `toNumber`, `clamp`
